# Use Case: Report Problem with Stop

## Goal in Context

A rider's client application submits a user-generated problem report regarding a specific transit stop (for example, if the stop name, stop number, or physical location is incorrect, or if an expected route or trip is missing from the stop). The server records the report for review by transit agency operations or data maintainers.

## Scope

OneBusAway REST API —
- `GET /api/where/report-problem-with-stop/{id}`
- `GET /api/where/report-problem-with-stop.json`

*(Note: The legacy Java Struts implementation supported `/api/where/report-problem-with-stop/{id}.json` and mapped `show`, `create`, and `index` to the same handler, accepting both GET and POST requests. Maglev registers both `GET /api/where/report-problem-with-stop/{id}` and `GET /api/where/report-problem-with-stop.json`. A trailing `.json` in the path does not become part of `{id}`, as `ExtractIDFromParams` (`internal/utils/http.go:11`) trims `.json` from the path parameter.)*

## Level

User goal

## Primary Actor

Rider (via a client application)

## Stakeholders and Interests

- **Rider** — wants an easy, reliable way to report errors or discrepancies with a bus stop, receiving confirmation that their report was recorded.
- **Transit Agency / Data Maintainer** — wants rider feedback to be structured, including coordinates, error codes, and descriptions to identify and fix data or physical signage inaccuracies.
- **Client Application** — expects a standard API envelope response confirming submission or returning validation errors for malformed parameters.

## Preconditions

- The caller supplies a valid API key (`key=<key>`).
- The stop ID is provided either as query parameter `stopId` (e.g., `stopId=1_75403`) or as the URL path segment `{id}` in the combined `agencyId_stopId` format.

## Minimal Guarantees

- All responses generated by the endpoint handler include `code`, `currentTime`, `text`, and `version` (client-canceled requests produce no response; router-level 404 responses for unmatched routes or 405 responses for unsupported methods are rejected before handler invocation).
- Non-context database storage failures return HTTP 500 with a standard JSON error envelope (`"internal server error"`, `version: 2`); context deadline expirations return HTTP 504, and canceled requests return client-canceled responses (producing no response when the client disconnected).
- Malformed coordinates or accuracy values return HTTP 400 with a field validation error envelope.

## Success Guarantees

- The problem report is stored in the database (`problem_reports_stop`) with timestamps (`created_at` and `submitted_at`) set to the current server time in milliseconds.
- Omitted optional parameters are stored as database `NULL`.
- HTTP status 200 is returned with a standard JSON response envelope containing `code: 200`, `text: "OK"`, `version: 2`, and an empty `data` object (`{}`).

## Trigger

A client issues an HTTP request to `GET /api/where/report-problem-with-stop/{id}?key=<key>&...` or `GET /api/where/report-problem-with-stop.json?key=<key>&stopId=<id>&...`.

## Main Success Scenario

1. The client supplies the stop ID either via query parameter `stopId` or as the path segment `{id}`, along with an API key and optional query parameters (`code`, `userComment`, `userLat`, `userLon`, `userLocationAccuracy`).
2. The server extracts the target stop ID using `extractAgencyCodeID` ([`report_problem_with_stop_handler.go#L19`](../internal/restapi/report_problem_with_stop_handler.go#L19), [`id_helpers.go#L35-L63`](../internal/restapi/id_helpers.go#L35-L63)). If `stopId` is present in the query string, it takes precedence over path `{id}` (matching legacy Java Struts, where bean property setters overwrite path values). If `stopId` is absent from the query string, the server falls back to the path segment `{id}` (with any `.json` extension stripped by [`utils.ExtractIDFromParams`](../internal/utils/http.go#L9-L12)). The server splits the combined ID on the first underscore character to obtain the agency ID and stop code.
3. The server parses and validates optional floating-point parameters (`userLat`, `userLon`, `userLocationAccuracy`).
4. If `userComment` is present, the server truncates the text to a maximum length of 500 characters.
5. The server records the report into the database with the raw stop code, problem code, comment, location coordinates, accuracy, and server timestamp ([`report_problem_with_stop_handler.go#L53-L70`](../internal/restapi/report_problem_with_stop_handler.go#L53-L70)). (Note: Maglev stores the raw stop code `stopCode`, whereas legacy Java stored the full agency-qualified `AgencyAndId`.)
6. The server returns HTTP 200 with an empty OK response envelope (`data: {}`) ([`ReportProblemWithStopAction.java#L109`](https://github.com/OneBusAway/onebusaway-application-modules/blob/095bf1ac3aeb7009b9f78e7f1cb4c65bd38b988a/onebusaway-api-webapp/src/main/java/org/onebusaway/api/actions/api/where/ReportProblemWithStopAction.java#L109), [`report_problem_with_stop_handler.go#L72`](../internal/restapi/report_problem_with_stop_handler.go#L72)).

## Extensions

**1a. The stop ID is missing or empty:**
- When neither a query parameter `stopId` nor a path `{id}` is supplied (e.g. `GET /api/where/report-problem-with-stop.json?key=TEST`), or if the resolved ID is empty, the server returns HTTP 400 with `code: 400`, `text: "id cannot be empty"`, and `data.fieldErrors.stopId` (or `data.fieldErrors.id` when using the path route). An unrouted path request to `/api/where/report-problem-with-stop/` returns HTTP 404 before handler invocation.

**1b. Stop ID contains no underscore (malformed combined ID):**
- If the resolved stop ID contains no underscore delimiter (e.g. `report-problem-with-stop/nounderscore.json` or `report-problem-with-stop.json?stopId=not-combined`), the server returns HTTP 400 with `code: 400` and `text: "invalid format: <id>"`, with the error reported in `data.fieldErrors.stopId` (if from query) or `data.fieldErrors.id` (if from path). *(Note: Legacy Java threw an unhandled exception via `AgencyAndIdLibrary.convertFromString` resulting in an HTTP 500 error envelope; Maglev's HTTP 400 validation error is an intentional deviation.)*

**2a. Malformed floating-point query parameters (`userLat`, `userLon`, `userLocationAccuracy`):**
- The server rejects non-numeric strings, NaN, or infinite values with HTTP 400 and a JSON validation error response containing `data.fieldErrors`.

**3a. Database failure or database uninitialized:**
- For non-context database errors, the server logs the error and returns HTTP 500 with a standard JSON error envelope (`"internal server error"`, `version: 2`). If a context timeout occurs (`context.DeadlineExceeded`), the server returns HTTP 504; client cancellations use `clientCanceledResponse`.

**4a. Missing or invalid API key:**
- The server returns HTTP 401 with `code: 401` and `text: "permission denied"`.

## Suspected Defects

### Defects that affect the use case

**1. Error response version hardcoded to 1 (defect DC-10).**

In legacy Java Struts, `ExceptionInterceptor.getExceptionAsResponseBean` ([line 72](https://github.com/OneBusAway/onebusaway-application-modules/blob/095bf1ac3aeb7009b9f78e7f1cb4c65bd38b988a/onebusaway-api-webapp/src/main/java/org/onebusaway/api/actions/api/ExceptionInterceptor.java#L72)) constructs error response envelopes with hardcoded `version: 1` regardless of the version requested by the client (version 2), and serializes the raw unhandled exception message in the `text` field. Successful responses use `version: 2`.

*Maglev intentionally corrects this — see [Implementation Decisions](#implementation-decisions).*

## Implementation Decisions

**Standardized 500 error envelope with version 2 (PR #1641, defect DC-10).**

When a non-context database persistence error occurs or the database is uninitialized, Maglev returns a standard OneBusAway JSON error envelope with HTTP status 500, `Content-Type: application/json`, `"version": 2`, `"code": 500`, and `"text": "internal server error"`. (Context deadline expirations return HTTP 504, and canceled requests return client-canceled responses.) This addresses defect DC-10 and avoids leaking internal database exception strings or returning plain text errors.

**Query-string stopId precedence and Android routing (#1726, #1757).**

Maglev routes both `GET /api/where/report-problem-with-stop/{id}` and `GET /api/where/report-problem-with-stop.json`. A non-empty query parameter `stopId` wins over the path `{id}`: Java applied the path ID first and the query string after it, and `setStopId` called `setId`, so query parameter `stopId` overwrites the path ID (e.g., `/report-problem-with-stop/1_path.json?stopId=1_query` stores `query`). When `stopId` is absent from the query string, the path ID is used as the fallback.

This supports Android OneBusAway, which submits problem reports without a path ID using `report-problem-with-stop.json?stopId=...`. When a query ID is missing or malformed, the validation failure is reported under `data.fieldErrors.stopId`; when the fallback path ID fails validation, the error is reported under `data.fieldErrors.id`.

**Malformed ID handling (HTTP 400 vs. Java exception).**

In legacy Java, `AgencyAndIdLibrary.convertFromString` threw an unhandled runtime exception when a combined ID was missing an underscore delimiter, producing an HTTP 500 error envelope. Maglev intentionally validates the combined ID format and returns HTTP 400 with a structured `fieldErrors` response (`"invalid format: <id>"`).

**Omitted optional parameters and coordinate NULL storage (PR #1641).**

When optional string query parameters (`code`, `userComment`) are omitted or empty, Maglev persists them as SQL `NULL` values using `nulls.NonEmptyString`, matching the legacy Java Struts behavior where unpopulated bean properties remain `null`.

For coordinate parameters (`userLat`, `userLon`, `userLocationAccuracy`), Maglev stores SQL `NULL` when they are omitted or empty. In legacy Java, `StopProblemReportBean` used primitive `double` fields, which caused omitted coordinates to be stored as `0.0`. Storing SQL `NULL` in Maglev is an intentional deviation from legacy Java to accurately represent missing location data.

**Ignored legacy parameters (data, time).**

Legacy Java Struts action `ReportProblemWithStopAction` included setters for `data` and `time` (via `ProblemReportBean`). Maglev does not persist or process these parameters and silently ignores them.

**Strict float parameter validation (PR #1490).**

Maglev strictly validates `userLat`, `userLon`, and `userLocationAccuracy` using `utils.ParseFloatParam`. Malformed strings (including `garbage`, `NaN`, `Inf`, and exponents like `1e999`) are rejected with HTTP 400 and an explicit `fieldErrors` structure. Explicit `0` values are accepted and preserved.

**User comment length limit.**

User comments are truncated to 500 characters (`utils.MaxCommentLength`) before storage to guard against unbounded payloads while preserving rider feedback.

**Deprecated API status.**

Problem reporting endpoints are in scope for Maglev 1.0 to preserve backward compatibility with legacy mobile clients, but the problem-reporting feature is deprecated per [[Maglev-1.0-Endpoint-Scope]] and is a candidate for redesign in a future API version.

## Response Structure

### Envelope

```json
{
  "type": "object",
  "properties": {
    "version":     { "type": "integer" },
    "code":        { "type": "integer" },
    "text":        { "type": "string" },
    "currentTime": { "type": "integer", "description": "Unix milliseconds" },
    "data":        { "type": "object" }
  },
  "required": ["version", "code", "text", "currentTime"]
}
```

**`version`** — `2` for Maglev responses and legacy success/validation responses; legacy Java unhandled server error envelopes use `version: 1` (see Defect DC-10).

**`code`** — HTTP status code (`200` on success, `400` for validation error, `401` for unauthorized key, `500` for server error, `504` for deadline exceeded).

**`text`** — Human-readable status description (`"OK"` on success, `"internal server error"`, `"permission denied"`, etc.).

**`currentTime`** — Server wall-clock time in Unix milliseconds when the response was constructed.

**`data`** — On success, an empty JSON object (`{}`). On validation errors, an object containing `fieldErrors`. Omitted on Maglev HTTP 500 server error responses.
